# Rokid Obsidian Knowledge Router

Rokidからの自由な質問に対し、Obsidian保管庫全体を外部AIへ渡さず、Mac内で関連箇所を絞るための読み取り専用検証です。

## 狙い

- 本人の記録、現在のシステム正本、執筆ルール、外部クリッピングを別種類の根拠として扱う。
- `必須資料一覧.md`は正本の場所を示す索引であり、実績そのものの根拠にはしない。
- `Clippings`の内容を「利用者自身の経験」と誤認させない。
- 旧資料、削除前バックアップ、試用ファイル、シンボリックリンクを既定で読まない。
- `ai_access: deny`のノートは候補に入れない。`confirm`は外部AIへ渡す前に確認が必要と示す。
- 保管庫は書き換えない。データベースやベクトルインデックもまだ作らない。
- 日付付き検証台帳は行単位で候補化し、現在・最新・実機確認の質問では、古い未確認より後日の合格を優先する。同日内は記録順を明示し、進捗質問では最終行を優先する。最新行で主語を省略していても、台帳全体で主体を確認し、行内の別の手掛かりから継続記録として扱う。
- 日付のない本人記録は、`その後`などの相対表現だけを手掛かりとして保持する。日付や別文書との順序は推測せず、日付付きの現在正本がある時は、日付不明文書の`現在`を最新状態として優先しない。

## 想定ルート

1. Lunaは質問文だけを見て、人物、期間、話題、検索語、必要な資料種別を構造化する。
2. Macが構造化された検索計画でObsidianを読み取り専用検索する。
3. 根拠の種別と送信可否を検査し、必要最小限の抜粋だけをLunaへ渡す。
4. Lunaはファイル名と見出しを根拠として回答し、不足時は推測せず一つ確認する。
5. 書き込み、送信、削除、購入などは別の安全な実行層とRokidの確認を通す。

## Lunaを含む二段階パイプライン

`knowledge-pipeline.mjs`は、ChatGPTログイン済みのアプリ同梱Codex CLIを使います。

- 1回目のLunaには質問文だけを渡し、検索計画をJSONで受け取る。
- Macが検索計画を検査してから保管庫をローカル検索する。
- `allow`の候補だけを最大6件・合計4,800文字までLunaへ渡す。
- `confirm`と`deny`は渡さない。存在しない根拠IDを引用した回答も拒否する。
- Lunaが機密度`high`と判定した質問は、明示許可なしにローカル検索へ進めない。
- APIキー関連の環境変数を除外し、ChatGPTログイン、Luna、読み取り専用、一時セッションを明示する。
- 各Luna実行でコマンド、ファイル、Webなどの道具使用を検出したら失敗にする。
- 一時プロンプト、構造化出力、選択抜粋は処理終了時に削除する。

```sh
node knowledge-pipeline.mjs \
  --vault "/path/to/your/ObsidianVault" \
  --question "私はRokidで、これまでどんな開発や実機試験をしてきた？"
```

標準出力には回答、根拠のファイル名・見出し、送信文字数、モデル実行監査を出します。抜粋本文そのものは結果へ再掲しません。

## ローカル検索だけの実行例

```sh
node knowledge-router.mjs \
  --vault "/path/to/your/ObsidianVault" \
  --query "Rokidでこれまでどんな開発をしたか" \
  --terms "Rokid,開発,実機,アプリ" \
  --required "Rokid" \
  --roles "personal_evidence,current_system_evidence" \
  --limit 12
```

返り値はJSONで、パス、見出し、根拠種別、外部AI送信前の確認要否、短い抜粋を含みます。

## まだ証明していないこと

- 日本語の自由な言い換え一文は実機合格したが、十分な再現率
- 日付のない文章は推測せず扱えるが、複数ファイルに分かれた履歴を自動で完全に並べること
- セッション指定の自由質問一文は固定経路の実機往復に合格。案内した利用者の実音声一文もRV101回答表示まで合格したが、複数の自由発話と日を変えた固定経路の安定性は未確認
